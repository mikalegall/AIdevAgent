<br/><br/>
Kun frontend skeleton on luotu AI avusteisesti, generoidaan AI avusteisesti [Penpot](https://penpot.app/penpot-mcp-server) leiskoihin perustuen [OpenAPI spec](https://spec.openapis.org/oas/v3.2.0.html). API dokumentaatioon perustuen ohjeistetaan AI Dev Agent aloittamaan [TDD](https://fi.wikipedia.org/wiki/Testivetoinen_kehitys), yksi toiminnallisuus kerrallaan, ja sekin pilkottuna pienempiin osiin, jotta katselmoitavat commitit olisivat mahdollisimman pieniä. Katselmoija voi ohjata neropattia (keinoäly) korjaamaan commitin virheet tai ihminen voi tehdä manuaalisesti korjaukset ja uuden commitin. Versiohistoriasta sitten näkee ennen push mitä kukakin on tehnyt.

## MCP-Server
TypeScriptillä tehdään myös [MCP-Server](https://github.com/modelcontextprotocol/servers). Lähtökohtaisesti MCP-Server kannattanee ehkä tietoturvasyistä tehdä itse (onneksi ne ovat tosi pieniä ja yksinkertaisia).
<br/><br/>
Skill on action tool. Kun kielimalli on kirjoittanut sähköpostin tai koodin, ei se osaa lähettää tai buildata sitä. Toiminnon tekemiseen tarvitaan taito (skill). Kielimalli on niin vanha kuin sen tuorein koulutusdata sattuu olemaan, Skill voi tarkistaa tämän hetken tilanteen (esim. ilmatilan sää, tuoreimmat uutisotsikot). Skill mahdollistaa siis vuorovaikutuksen fyysisen maailman kanssa kuten esim. tiedoston kirjoittamisen kiintolevylle tai REST-API kutsun triggeröimisen.
<br/><br/>
AI agentti saa MCP-client avulla tietää MCP-palvelimelta, ikään kuin Swagger dokumentaationa, mitä Tool sillä on käytettävissään (Skill on Tool) ja mitä Resource sillä on käytettävissään (tiedon lukemisen siirrossa MCP-protokollaa tukeva tietolähde). Resource voi olla vaikka hesarinEtusivunTuoreimmatUutisnostot tai asiakas_data.csv tai CRM/ERP tarjoama MCP-rajapinta. Mikäli esim. Hesari ei tarjoa tietoa MCP-rajapinnan kautta, niin silloin siihen käytetään Skill, joka triggeröi REST-API kutsun. Käytännössä siis ehkä joskus Hesari alkoi jossain vaiheessa tarjoamaan REST-API lisäksi GraphQL endpointia ja seuraavaa kehitys askel on tarjota MCP-protokollaa http rinnalla.
<br/><br/>
AI agentti voi olla myös AI Dev Agent, jolloin aluksi se ei tarvitse koodaamiseen MCP-palvelinta. Silloin riittää läppärille paikallisesti asennettu [Ollama](https://ollama.com/) moottori pyörittämään paikallisesti ladattuja kielimalleja ja Podman konttiin eristetty [Aider](https://aider.chat/) tekemään koodaustyön. Podman eroaa Dockerista sillä, että Podmanilla ei ole koskaan pääkäyttäjän oikeuksia tai lisenssimaksuja ja Podman on daemonless (siinä ei ole taustalla pyörivää keskitettyä hallintaprosessia). Konttiin niin sanotusti mountataan yksi läppärillä oleva kansio ja sen sisälle rajoittuu AI Dev Agent (Aider) oikeus toimia eli kirjoittaa koodia Sandboxissaan. Temmellyskentässä on vain kaksi aukkoa kontista ulos maailmaan isäntäkoneelle, reititys Ollamaan (joka pyörittää paikallisesti ladattuja ilmaisia kielimalleja näytönohjaimessa, prosessorissa ja keskusmuistissa ilman token laskutusta) sekä mountattuun hakemistoon. Käytännössä se mountattava kansio on perustetun projektin ”juuri” eli sama kuin olisi kloonannut versionhallinnasta repositoryn omalle koneelle. Vaikka ne tuntuvat riskiltä ilmatiiviissä eristyksessä, niin ne ovat sekä laskelmoituja että hallittuja riskejä. Jos Agentti sekoaa kontin sisällä, ei se pääse käsiksi isäntäkoneen muihin tiedostoihin (kuten selaimen evästeisiin tms.), eikä se voi suorittaa komentoja suoraan käyttöjärjestelmän ytimessä, tai pysty skannaamaan tai saastuttamaan lähiverkkoa, koska sen näkyvyys rajoittuu vain sille nimenomaisesti sallittuihin resursseihin.

## AI-editor
Integrated Development Environment (IDE) voi olla myös sellainen johon AI on rakennettu ydintoiminnoksi eikä AI-plugariksi. Tällainen AI-editor on [Cursor](https://cursor.com/home). Sillä ei toistaiseksi taida olla off-line käyttömahdollisuutta, mutta jos internet käyttö ja MCP ei ole este, niin sillä kannattaa pääsiäisenä 2026 aloittaa aiheeseen tutustuminen.
